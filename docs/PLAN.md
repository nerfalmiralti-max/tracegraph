# TraceGraph: план исследования и продукта

## Фокус V1

Только **публичные сайты интернет-магазинов**, с отдельным признаком вида: «неизвестен / совпадает со списком угроз / есть документированные связи / требуется проверка». Никаких публичных обвинений против людей по одному косвенному признаку.

## Границы безопасности

- Не принимать реквизиты карт, документы, адреса проживания, переписку с пострадавшими в публичную базу.
- Обход CAPTCHA, закрытых аккаунтов, закрытых API и агрессивный scraping запрещены.
- Данные от заявителей приватны до независимой проверки; источники, даты и история изменения решения обязательны.
- Вклад пользователя ≠ установленный факт; право на оспаривание и удаление персональных данных.
- Похожие шаблоны могут быть у легитимных магазинов, созданных на одной платформе: связь ≠ обман.
- Никаких запросов с сервера к произвольным URL посетителя без SSRF-защиты, sandbox и политики разрешённых адресов.
- Не публиковать граф с личными телефоном, адресом проживания, email частного лица.

## Roadmap

**Этап 1 — прототип (сейчас):** UI, приём доменов, API Web Risk с согласованными условиями, тесты. Всё демонстрационное явно отмечено.

**Этап 2 — первые данные (2–4 недели):** хранилище PostgreSQL для доменов, доказательств и их источников; ручной review 100 документированных кейсов и 100 добросовестных сайтов; показатели ложноположительных срабатываний.

**Этап 3 — граф связей (1–3 месяца):** совпадения по *разрешённым к сбору* публичным текстовым и визуальным отпечаткам; независимая проверка как минимум двух сигналов; интерфейс с источниками, датами, жалобами и апелляциями.

**Этап 4 — MVP на реальных людях (3–6 месяцев):** уведомления об изменении статуса сохранённых магазинов, RU/EN, прозрачная политика данных, бета-группа 50–100 человек. Конверсия и удержание важнее загрузок.

**Этап 5 — расширение (6–18+ месяцев):** региональные рынки, браузерное расширение, семейные подписки, контрольный набор новых угроз, открытые проверяемые метрики точности.

### Минимальные метрики до платного запуска
- Количество доменов с независимым подтверждением, а не просто жалобой.
- Precision у предупреждений высокого риска и отдельно доля false positives на добросовестных сайтах.
- Время до появления реальной угрозы в базе.
- Доля пользователей, вернувшихся к проверке в течение 30 дней.
- Готовность платить за **повторяющиеся** уведомления, а не одноразовые проверки.

> Не выдавать рекламу «защита гарантирована» и не монетизировать публичное обвинение владельца домена.
